How PayBee Keeps
Your Money Safe

Security on PayBee isn't a feature added on top. It's built into every step of how the platform works.

Hard Lock Escrow

When a seller posts a trade ad, the platform moves that USDT amount from their available balance into a hard-locked escrow account. This happens atomically — it's a single database transaction that cannot be partially completed.

The USDT cannot be withdrawn, transferred, or used in another trade while the lock is active. If the trade fails or times out, the funds return to the seller automatically.

₮

Evidence-Based Settlement

No USDT is ever released based on a claim alone. The buyer must upload a screenshot of their bank transfer. That file is hashed using SHA-256 the moment it's received — the hash is stored permanently and the file becomes read-only.

The seller then reviews the screenshot manually. Only after the seller actively confirms receipt — using their PIN or 2FA token — does the ledger update and the USDT move.

Any screenshot with tampered metadata is rejected by the system before it reaches the seller.

On-Chain Deposit Verification

Every USDT deposit goes through a strict five-stage verification loop. Your transaction ID is submitted, an admin queries the blockchain explorer directly, the amount and confirmation count are checked against the expected values, and the balance is only credited after all conditions are met.

We verify every deposit on TRC20, ERC20, and BEP20 independently using their respective blockchain APIs.

Cryptographic Ledger Chain

Every entry in the PayBee ledger includes the SHA-256 hash of the previous entry. This creates a chain — identical in principle to how blockchains work — where any attempt to alter a historical record breaks the chain.

We run automated integrity checks nightly and alert immediately on any break. Balances are always accurate and tamper-evident.

Encryption Everywhere

Bank account details and personal identification information are encrypted using AES-256-GCM at rest. All data in transit is protected by TLS 1.3 as a minimum.

Session tokens expire every 15 minutes and rotate on each use. Encryption keys are managed through a dedicated key management system with scheduled rotation.

Every Action Is Logged

The audit trail captures every user action, every admin decision, and every system state change. Each log entry includes who did it, what they did, which record was affected, what it looked like before and after, the IP address, the device, the session ID, and a UTC timestamp.

The log is append-only — no entry can be updated or deleted. Each log entry is signed with an HMAC for tamper detection.

Admin Oversight

No account goes live without admin activation. No deposit is credited without admin verification. No escrow override can happen without a written reason recorded in the audit trail. Large withdrawals require dual-admin approval.

This level of oversight means that even if a user attempts to manipulate the system, there is always an admin checkpoint before anything consequential happens.

Two-Factor Authentication

2FA is mandatory for all admin accounts and strongly recommended for all users. It is required for login, withdrawal approvals, and trade confirmations.

If you lose access to your 2FA device, account recovery requires full identity reverification matching your original KYC records.
